# 验证记录 — 2026-10-16

- 编译：通过 — PlatformIO 6.1.19、espressif32 6.7.0、Arduino ESP32 2.0.16；默认工程和独立 Demo 两个环境。
- 主机测试：未运行 — 尚无独立主机测试框架。
- 架构检查：通过 — 最小入口、BSP 与应用边界、公开依赖和凭据检查。
- 真机测试：部分完成 — 实机为 ESP32-S3 revision v0.2，设备保存的 HardwareVersion 为 v2.1.0，16MB Flash、约 8MB PSRAM。仓库仅支持这一硬件版本。

## 已观察到的结果

操作者确认两个实体按键为 Mode（GPIO4）和 Voice（GPIO3），已观察到按下/松开和正确的录音/回放灯色变化。启动短音、常亮绿灯通过人工确认。Flash 为 16MB；运行时报告 8386279 字节 PSRAM，256KB PSRAM 模式读写测试通过。GPIO12/13 上检测到 0x19、0x62、0x6b，0x19 的 LIS3DH WHO_AM_I 为 0x33。后两个地址与原仓库的电量计/充电芯片定义吻合，但未验证其功能。

本地诊断对比了 32 位双声道输入和原 ONLY_LEFT 单声道配置，以扬声器输出 1kHz 测试音作对照。两种配置均采到测试音：双声道有效槽 RMS 从 33.9 升至 7093.6，单声道从 70.4 升至 7226.8，第二声道槽为零。因此没有据此更改 BSP 的麦克风声道或引脚。操作者听到了录制测试音的回放，随后确认在 10–15 厘米距离可以录到并回放人声，但音量偏小。导出录音中的人声电平低，松键瞬态占据峰值。同一诊断固件运行期间观察到空闲堆稳定。

独立 Demo 现支持按住 Voice 录音（最长十秒）、松开回放、内存保留原始 PCM 和串口导出。回放默认放大 8 倍并限幅至 ±30000，按住录音的回放跳过末尾 80 毫秒以减轻松键声。这些调整仅属于 Demo，原始 PCM 导出不变。编译和边界检查通过。操作者确认 4 倍回放清楚但偏小，再对同一段录音进行 8 倍回放后确认“音量合适，声音清楚”。这次回放 102400 个样本，返回 ESP_OK，限幅样本数为零。已将通过验收的 8 倍设置固化为 Demo 默认值。

## 尚未通过的验收项

原始电平的人声已可听回放，但音量小；8 倍调试回放通过人工验收。旋钮调音与硬件开关机已通过人工确认：从小到大平滑变化，关机灯灭、再次开机恢复绿灯；串口记录两次 POWERON 和 ESP_OK 音频初始化。GPIO8 首次停留约 1866，后续开机操作测到 1145、1401、1609 等更低值，最大为 4095；因此不把首次停留值写死为端点。Demo 沿用原产品 0–4095 ADC 量程，将提示音和 8 倍人声回放缩放至 5%–100%，带平滑与数据块内渐变。该调音策略仅在 Demo 中，BSP 继续提供原始 ADC/PCM。循环提示音在重启后默认关闭，这曾造成一次“重新开机无声”的误判；重新开启后操作者确认调音正常。精确机械端点和声压标定尚未完成。电池/充电功能、供电和长时间可靠性未测试。

## 数据保护与复现

沿用生产分区表，只将诊断应用写入 app0（0x410000），再通过 otadata 选择启动。原 factory 应用保留。前后比对确认分区表与设备身份分区均未变化，身份原始数据不入库。本流程不向生产实机刷入开发分区表。

编译复现：`./tools/build.sh`；边界检查：`python3 tools/check_boundaries.py`。串口命令和实体按键操作见 [BSP.zh_CN.md](BSP.zh_CN.md)。真机结果只适用于本次设备和诊断镜像，不代表所有外设或生产应用均已验证。
